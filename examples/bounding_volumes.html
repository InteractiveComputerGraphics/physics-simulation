Bounding volumes

Testing two complex objects for intersection exactly is expensive. A bounding volume (BV) is a simple shape that completely encloses an object. If the bounding volumes of two objects do not overlap, the objects cannot overlap either, and the expensive exact test can be skipped. Collision detection therefore becomes a two-stage process:

  1. BV test: do the bounding volumes overlap? This test is cheap and conservative. It never misses a real collision (no false negatives), but it may report an overlap although the objects are apart (a false positive).
  2. Exact test: only if the BVs overlap, test the actual geometry (here: two convex polygons with the separating axis theorem; in 3D, typically triangle–triangle tests, often organized in a bounding volume hierarchy).

A good bounding volume should (i) fit the object tightly, so that false positives are rare, (ii) have a cheap overlap test, (iii) be cheap to update when the object moves or rotates, and (iv) need little memory. These goals contradict each other; the four types below are different trade-offs between them. The example works in 2D, so spheres become circles. The 3D numbers are given alongside.

Bounding sphere

A sphere is stored as center $\mathbf c$ and radius $r$. Two spheres overlap if and only if $$\|\mathbf c_A - \mathbf c_B\|^2 \le (r_A + r_B)^2,$$ which is a single test and needs no square root. A sphere is rotation invariant: when the object rotates, only the center has to be transformed. It fits elongated or flat objects badly, though (try the "Elongated" objects and compare the area ratios). The example computes the minimal enclosing circle with Welzl's randomized algorithm [Wel91]. Ritter's fast approximation [Rit90] is a common alternative in practice.

Axis-aligned bounding box (AABB)

An AABB is stored as minimum and maximum coordinate per world axis. Two AABBs overlap if and only if their intervals overlap on every coordinate axis: $$\min{}_A^i \le \max{}_B^i \;\wedge\; \min{}_B^i \le \max{}_A^i \qquad \text{for } i = x, y\,(,z).$$ That is 2 interval tests in 2D, 3 in 3D, and the test can stop as soon as one axis separates the boxes. The test is very cheap, but the box must stay aligned with the world axes. When the object rotates, the AABB has to be recomputed (here from all vertices) and its size changes with the orientation. Switch on "Auto-rotate" to watch the area ratio of the AABB change while those of the sphere and the OBB stay constant.

Oriented bounding box (OBB)

An OBB is stored as center $\mathbf c$, an orthonormal frame $\mathbf u_1, \mathbf u_2\,(,\mathbf u_3)$ and half extents $h_i$. It rotates with the object, so its fit does not depend on the orientation. Its overlap test uses the separating axis theorem (SAT): two convex objects are disjoint if and only if there is an axis $\mathbf L$ on which their projections are disjoint. Let box $A$ have center $\mathbf c_A$, axes $\mathbf u^A_i$ and half extents $h^A_i$, and box $B$ correspondingly $\mathbf c_B$, $\mathbf u^B_i$, $h^B_i$. The projection of box $A$ onto $\mathbf L$ is the interval $[\mathbf c_A \cdot \mathbf L - r_A,\ \mathbf c_A \cdot \mathbf L + r_A]$ with the projected radius $$r_A = \sum_i h^A_i \,|\mathbf u^A_i \cdot \mathbf L|,$$ i.e. half the length of the box's shadow on $\mathbf L$ (each half extent contributes according to how much its axis points along $\mathbf L$). The radius $r_B = \sum_i h^B_i \,|\mathbf u^B_i \cdot \mathbf L|$ of box $B$ is defined in the same way. The two intervals are disjoint, i.e. the boxes are separated on $\mathbf L$, if the distance of the projected centers exceeds the sum of the projected radii: $$|(\mathbf c_B - \mathbf c_A)\cdot \mathbf L| > r_A + r_B.$$ For unit-length $\mathbf L$ these are true distances; for an arbitrary $\mathbf L$ both sides scale by $\|\mathbf L\|$, so the test result is the same and no normalization is needed. For boxes it suffices to test the following candidate axes:

  • 2D: the 2 axes of $A$ and the 2 axes of $B$ — 4 tests.
  • 3D: the 3 face normals of $A$, the 3 face normals of $B$ and the 9 cross products $\mathbf u^A_i \times \mathbf u^B_j$ of their edge directions — 15 tests [GLM96].

So the OBB fits much tighter than the AABB, but its test is more expensive. Fitting is harder too: the example offers the minimal-area rectangle (in 2D, one side is always collinear with a convex hull edge) and the common PCA fit. The PCA fit aligns the box with the eigenvectors of the covariance matrix of the vertices. It is fast but not optimal and depends on how the vertices are distributed; compare both fits with the "Random convex" objects.

Discrete oriented polytope (k-DOP)

A k-DOP generalizes the AABB to $k/2$ fixed directions $\mathbf n_1, \dots, \mathbf n_{k/2}$ that are the same for all objects. It stores the interval $[\min_{\mathbf p} \mathbf p\cdot\mathbf n_i,\ \max_{\mathbf p} \mathbf p\cdot\mathbf n_i]$ of the object for each direction, i.e. $k$ numbers. The BV itself is the intersection of the $k$ resulting half-spaces (slabs). Because the directions are shared, the overlap test is just a comparison of $k/2$ interval pairs, with no projection at query time: $$\text{overlap} \iff \min{}_A^i \le \max{}_B^i \;\wedge\; \min{}_B^i \le \max{}_A^i \qquad \text{for } i = 1,\dots,k/2.$$ An AABB is the 4-DOP in 2D (6-DOP in 3D). Typical 3D choices are 6-, 14- (adds the 4 cube diagonals), 18- (adds the 6 edge diagonals) and 26-DOPs [KHM98]. A larger $k$ fits tighter but costs more memory and more interval tests. Like the AABB, a k-DOP must be recomputed when the object rotates.

In 2D, comparing the $k/2$ intervals is an exact test for the two k-DOPs, since their edge normals are exactly the fixed directions. In 3D, the cross products of edge directions would also be needed, so the $k/2$ interval comparisons are only conservative. They can report overlap for two disjoint k-DOPs, which is acceptable for a BV test.

A tighter BV means fewer false positives and thus fewer expensive exact tests, but each BV test costs more. Which type pays off depends on the application. In bounding volume hierarchies, the same trade-off appears at every node: AABB trees are cheap to refit for deforming meshes [vdB97], while OBB trees prune very effectively for rigid objects in close proximity [GLM96].
