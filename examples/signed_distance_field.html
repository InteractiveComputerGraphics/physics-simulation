Signed distance fields

The signed distance function of a closed object $\Omega$ with surface $\partial\Omega$ assigns to every point $\mathbf x$ its distance to the surface, with a negative sign inside: $$\phi(\mathbf x) = s(\mathbf x)\, \min_{\mathbf y \in \partial\Omega} \|\mathbf x - \mathbf y\|, \qquad s(\mathbf x) = \begin{cases} -1 & \mathbf x \in \Omega \text{ (inside)} \\ +1 & \text{otherwise (outside)}. \end{cases}$$ So the surface is the zero level set $\phi(\mathbf x) = 0$. For collision detection, a single evaluation of $\phi$ answers several questions at once:

  • Collision test: $\phi(\mathbf p) < 0$ means that the point $\mathbf p$ penetrates the object.
  • Penetration depth: $|\phi(\mathbf p)|$.
  • Contact normal: the gradient $\mathbf n = \nabla\phi(\mathbf p)$ points away from the closest surface point. Since $\phi$ is a distance, $\|\nabla\phi\| = 1$ almost everywhere (the Eikonal equation).
  • Closest surface point: $\mathbf c = \mathbf p - \phi(\mathbf p)\, \nabla\phi(\mathbf p)$.

For simple shapes like spheres and boxes, $\phi$ has a closed-form expression (see the sphere and box examples). For a general object, given as a triangle mesh in 3D or as a polygon in 2D as in this example, computing the exact distance means finding the closest of all triangles (edges), which is far too slow to do for every query. The common solution is to precompute $\phi$ on a regular grid once and to interpolate it at runtime. The result is called a signed distance field (SDF).

The grid

The SDF is a regular grid of $n_x \times n_y$ square cells of size $h$ (cubes and $n_x \times n_y \times n_z$ cells in 3D) that stores one value per grid node, i.e. per cell corner. The grid is defined by three things:

  • The domain. The grid has to cover the region in which queries can occur. Usually this is the axis-aligned bounding box $[\mathbf b_{\min}, \mathbf b_{\max}]$ of the object, enlarged on all sides by a margin $m$: $$\mathbf x_0 = \mathbf b_{\min} - (m, m)^T, \qquad \mathbf x_{\max} = \mathbf b_{\max} + (m, m)^T.$$ The origin $\mathbf x_0$ is the corner of the domain with the smallest coordinates, and it is the position of node $(0,0)$. The margin is needed because collision queries happen near the surface, also outside of it: a point that is about to collide lies just outside the object, and its distance must still be available. A typical choice is a few cells, or the largest distance at which the application still needs a value, e.g. the collision tolerance or the radius of the particles.
  • The resolution. For a chosen cell size $h$, the number of cells per axis is $$n_x = \left\lceil \frac{x_{\max} - x_0}{h} \right\rceil, \qquad n_y = \left\lceil \frac{y_{\max} - y_0}{h} \right\rceil.$$ Alternatively, one fixes $n_x, n_y$ and computes $h$ from the size of the domain. Rounding up makes the grid slightly larger than the domain, which does no harm.
  • The node positions. Node $(i, j)$ with $i = 0,\dots,n_x$ and $j = 0,\dots,n_y$ lies at $$\mathbf x_{ij} = \mathbf x_0 + \begin{pmatrix} i\,h \\ j\,h \end{pmatrix},$$ and stores the value $\phi_{ij} = \phi(\mathbf x_{ij})$. Positions are never stored; they follow from $\mathbf x_0$, $h$ and the indices. Conversely, the indices of the cell that contains a point follow from its position (see the query below), so finding the cell needs no search at all.

Storage. The values are kept in a flat array, typically row by row: node $(i,j)$ is stored at index $k = j\,(n_x+1) + i$, in 3D node $(i,j,l)$ at $k = \big(l\,(n_y+1) + j\big)(n_x+1) + i$. The grid has $(n_x+1)(n_y+1)$ nodes in 2D and $(n_x+1)(n_y+1)(n_z+1)$ in 3D. Halving $h$ multiplies the memory by 4 in 2D and by 8 in 3D. For example, a $256^3$ grid already needs about 17 million values ($257^3$ nodes, about 68 MB with 4-byte floats). This is why the cell size is a trade-off between accuracy and memory.

Queries outside the domain. Outside the grid, no values are available. Depending on the application, such a query is simply reported as "far away, no collision", or the point is clamped to the domain and the distance from the point to the domain is added as a conservative estimate.

Moving objects. For a rigid body, the grid is defined once in the body's local coordinate system, so $\mathbf x_0$ and the grid axes move with the body. A query point is first transformed into the local system, $\mathbf p_{\text{local}} = \mathbf R^T(\mathbf p - \mathbf t)$, and the resulting normal is rotated back to world coordinates with $\mathbf R$.

Construction: computing the value at a grid node

The value of each node is computed in two independent parts:

  1. Unsigned distance: the distance to the closest point of the surface. Here, this is the minimum distance over all polygon edges $\overline{\mathbf a\mathbf b}$. The closest point on an edge is found by projecting onto the edge's line and clamping to the segment: $$t = \text{clamp}\!\left(\frac{(\mathbf x - \mathbf a)\cdot(\mathbf b - \mathbf a)}{\|\mathbf b - \mathbf a\|^2},\ 0,\ 1\right), \qquad \mathbf c = \mathbf a + t\,(\mathbf b - \mathbf a), \qquad d = \|\mathbf x - \mathbf c\|.$$ If $t$ is clamped to 0 or 1, the closest feature is a vertex, otherwise the interior of the edge. In 3D, the corresponding operation is the point–triangle distance, where the closest feature can be a vertex, an edge or the triangle's interior.
  2. Sign: inside or outside? The example casts a ray from the node in the $+x$ direction and counts how often it crosses the polygon: an odd number of crossings means inside (even–odd rule). In 3D, robust alternatives are the angle-weighted pseudo-normal of the closest feature [BA05] and generalized winding numbers.

The dashed circle around the selected node has radius $|\phi_{ij}|$ and touches the polygon only at the closest point; no part of the surface lies inside it. Testing every node against every edge costs $O(\#\text{nodes} \cdot \#\text{edges})$ (see the statistics). Practical implementations accelerate this, e.g. by finding the closest triangle with a bounding volume hierarchy, by computing exact distances only in a narrow band around the surface and propagating them outward with the fast marching [Set96] or fast sweeping [Zha05] method, or by adaptive grids [KDBB17]. Since construction happens once in a preprocessing step, its cost matters much less than the cost of a query. Use "Build step by step" to watch the nodes being computed one after another.

Distance query: evaluating the field at an arbitrary point

A query at a point $\mathbf p$ only needs the four nodes (eight in 3D) of the cell that contains $\mathbf p$:

  1. Find the cell and the local coordinates $s, t \in [0,1]$ of $\mathbf p$ inside it: $$i = \left\lfloor \frac{p_x - x_0}{h} \right\rfloor,\quad j = \left\lfloor \frac{p_y - y_0}{h} \right\rfloor,\qquad s = \frac{p_x - x_0}{h} - i,\quad t = \frac{p_y - y_0}{h} - j.$$
  2. Interpolate bilinearly: first along $x$ on the two cell edges, then along $y$ between the results: $$a = (1-s)\,\phi_{i,j} + s\,\phi_{i+1,j}, \qquad b = (1-s)\,\phi_{i,j+1} + s\,\phi_{i+1,j+1}, \qquad \phi(\mathbf p) \approx (1-t)\,a + t\,b.$$ In 3D, trilinear interpolation does the same with the 8 corners of a cell (7 linear interpolations).
  3. Gradient (if a normal is needed): differentiate the interpolant, e.g. $\frac{\partial\phi}{\partial x} = \frac{1}{h}\big((1-t)(\phi_{i+1,j} - \phi_{i,j}) + t\,(\phi_{i+1,j+1} - \phi_{i,j+1})\big)$, and normalize it.

So a query costs a constant number of operations, independent of how complex the object is. This is the main advantage of SDFs. For a moving rigid body, the field is stored in the body's local coordinate system and the query point is transformed into this system first. For a deforming object, the field would have to be recomputed.

Accuracy

The interpolated field is only an approximation; compare the exact polygon (solid) with the reconstructed zero level set (dashed) and the interpolation error in the statistics. The error is largest where the true distance function is not smooth:

  • Sharp corners (star, L-shape) are rounded off by the interpolation.
  • Inside the object, $\phi$ has kinks along the medial axis, where two surface parts are equally close.
  • Features thinner than the cell size can disappear completely: try the "Thin feature" shape with $h = 40$ and then refine the grid.

Finer grids reduce the error but need more memory. Adaptive grids and higher-order interpolation (e.g. cubic polynomials per cell) reach a given accuracy with far fewer values [KDBB17].
